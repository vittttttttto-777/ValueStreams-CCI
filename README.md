# Потоки создания ценности · Coral Club

Автономное веб-приложение для стратегической сессии «Зоны ответственности».
Пять потоков создания ценности, их шаги, функции на шагах и роли
«владелец / помощник / претендент», закрепление ролей с метрикой и сроком,
карта связей, цепочка ценности с владельцами на шагах и режимом показа,
памятка по ролям, матрица «функция × поток» и реестр споров.
Интегратор каждой команды входит по паролю и редактирует только свой поток.

Статический сайт без сборки. Данные хранятся в Supabase:
у каждого потока свои таблицы, сводная матрица строится представлениями.

```
├── index.html                  приложение
├── config.js                   адрес и publishable-ключ Supabase
├── i18n-en.js                  английский словарь интерфейса и данных
├── favicon.svg, *.png          иконка сайта
├── vendor/supabase.js          supabase-js 2.117.1 (MIT)
├── fonts/                      Suisse Int'l и Newton (дизайн-система Coral Club)
├── supabase/migrations/        схема и начальные данные
├── supabase/queries.sql        готовые запросы: матрица, споры, пересмотры
├── data/                       исходная модель в JSON и CSV
└── netlify.toml
```

## Языки

Переключатель RU / EN в шапке, выбор запоминается в браузере. Переводится весь интерфейс,
памятка, карта связей, потоки, шаги отраслевой модели, точки накала и группы функций.
Названия функций в EN берутся из поля English справочника функций.
Текст, который команды вводят сами (новые шаги, метрики, заметки), показывается как введён.
Новую фразу интерфейса добавьте в `i18n-en.js`: `exact` — фраза целиком, `patterns` — шаблон с {0}, {1}.

**Тексты, которые вводят команды** (названия шагов, содержание, результат, KPI, заметки), переводятся через таблицу `vs_i18n` в Supabase: `src` — исходный текст, `en` — перевод на английский (для русских текстов), `ru` — перевод на русский (для английских). Если команда меняет текст, старый перевод перестаёт совпадать и показывается исходник, пока не добавлен новый перевод. Что ещё не переведено, показывает представление `vs_i18n_missing`:

```sql
select * from vs_i18n_missing;                                   -- что перевести
insert into vs_i18n(src, en) values ('Русский текст', 'English text')
  on conflict (src) do update set en = excluded.en;             -- добавить перевод
```

Тексты потоков VS2C, VS6, VS7 из предложения v0.4 переведены в `i18n-en.js`, поэтому тоже видны в `vs_i18n_missing`, но на сайте уже показываются на английском.

## Структура базы

Все объекты начинаются с `vs`, чтобы не пересекаться с другими приложениями проекта.

**Справочники**

| Таблица | Содержимое |
|---|---|
| `vs_functions` | 25 функций (справочник 25.09.2026) и функции, добавленные на сессии (`is_custom`) |
| `vs_streams` | 8 потоков, код для показа (`code`, VS2 → VS2D), источник (`origin`: `v0.4` = из предложения), команда трека, ценность, KPI, журнал правок шагов |
| `vs_hot_points` | точки накала из свода анкет 17.09.2026 |
| `vs_users`, `vs_sessions` | учётные записи интеграторов и сессии входа (из браузера не читаются) |

**По каждому потоку** (`vs1` … `vs5`, `vs2c`, `vs6`, `vs7`)

| Таблица | Содержимое |
|---|---|
| `vsN_steps` | шаги потока: порядок, название, результат, метрика владельца, срок закрепления, сменщик, заметка, история. Удалённый командой шаг получает `active = false` и может быть возвращён |
| `vsN_roles` | функции на шагах: `owner` владелец, `helper` помощник, `claimant` претендент, `none` участвует без роли. У шага не может быть двух владельцев |

| Поток | Команда |
|---|---|
| VS1 Развивать продуктовый портфель | CoralEVO |
| VS2D Формировать клиентский спрос (дистрибьютор) · в базе id `VS2` | PrimeGrowth |
| VS2C Формировать осознанный клиентский спрос (потребитель) | из предложения v0.4, редактирует администратор |
| VS3 Исполнять клиентский заказ | ITModel |
| VS4 Обеспечивать успех клиента | HealthOS |
| VS5 Развивать партнёрскую сеть | GrowthModel |
| VS6 Сопровождать партнёрский бизнес | из предложения v0.4, редактирует администратор |
| VS7 Развивать бренд и доверие | из предложения v0.4, редактирует администратор |

Потоки VS2C, VS6, VS7 добавлены 28.09.2026 из «Модели потоков v0.4» (миграции `…0007`, `…0008`). Откат без потери данных VS1–VS5: `supabase/backup/rollback_v04.sql`.

**Сводные представления** (обновляются сами, отдельно их заполнять не нужно)

| Представление | Что показывает |
|---|---|
| `vs_all_steps`, `vs_all_roles` | шаги и роли всех пяти потоков одной таблицей |
| `vs_step_status` | каждый шаг: владелец, помощники, претенденты, статус, метрика, просрочен ли пересмотр |
| `vs_matrix` | матрица «функция × поток»: сколько шагов функция ведёт, поддерживает, оспаривает |
| `vs_disputes` | реестр споров за владение |

## Доступ по ролевой матрице

| Кто | Редактирует | Видит вкладки |
|---|---|---|
| Без входа | ничего, только просмотр | Портфель, Профиль потока, Карта связей, Цепочка ценности, Памятка по ролям |
| Интегратор команды (vs1…vs5) | только шаги, функции и роли своего потока | те же, что без входа |
| Администратор (admin) | все потоки и справочник функций | все, включая «Функции в потоках», «Справочник функций» и «Споры и закрепления» |

Права проверяет сама база (RLS): даже в обход интерфейса интегратор не сможет изменить чужой поток.
Вход — кнопка «Войти» в шапке, по паролю. Регистр букв и пробелы по краям не важны. Сессия живёт 14 дней.

**Пароли в репозитории не хранятся.** Задать или сменить пароль — Supabase → SQL Editor:

```sql
select public.vs_set_password('vs1',   'новый пароль');  -- VS1 · CoralEVO
select public.vs_set_password('vs2',   'новый пароль');  -- VS2 · PrimeGrowth
select public.vs_set_password('vs3',   'новый пароль');  -- VS3 · ITModel
select public.vs_set_password('vs4',   'новый пароль');  -- VS4 · HealthOS
select public.vs_set_password('vs5',   'новый пароль');  -- VS5 · GrowthModel
select public.vs_set_password('admin', 'новый пароль');  -- администратор
```

Смена пароля сразу завершает все сессии этой учётной записи.
Вкладки, скрытые от интеграторов, задаются в `index.html` константой `TAB_ADMIN_ONLY`.

## Что где менять

- Состав шагов, функции на шагах, роли — в самом приложении, всё пишется в базу.
- Справочник функций — во вкладке «Справочник функций» (администратор): добавить, переименовать, сменить группу и порядок, скрыть неиспользуемую. Удалить функцию нельзя, только скрыть: на неё могут ссылаться шаги.
- Команды и тексты потоков — в таблице `vs_streams`.
- Карта связей, критерии коммерческой готовности, обратные связи — в `index.html`.
